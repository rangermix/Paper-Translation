## 1. 排序与交付方式

先解决丢失输入、误判译文和手机主要路径，再整理高频工作流，最后打磨视觉与选择器。
同一页面中的低优先级问题可随高优先级改动一起交付，避免重复重构；
不能因为整段编辑较复杂，就只改文案后宣布全部 P1 完成。
文案、键盘与响应式检查跟随功能包，不等最终阶段才处理。

| 阶段 | 交付包 | 主要范围 | 阶段完成结果 |
| --- | --- | --- | --- |
| 准备 | W00 | 复核源码、证据、部署与验收输入 | 对准当前状态，不把历史审查当作当前验证 |
| 1 可信交互 | W01–W04 | 全部 P1；同编辑页的 F07/F08 一并处理 | 输入有保护，译文状态可信，手机详情/导航/上传可用，段落连续编辑 |
| 2 核心工作流 | W05–W08 | 文库、管理、版本、导出、任务、校对与搜索的 P2 | 阅读、处理、编辑和导出路径清楚且保留历史语义 |
| 3 工具与阅读连续性 | W09–W11 | 术语、翻译记忆、设置、阅读器的 P2 | 专业功能可理解，在线返回明确，离线仍独立 |
| 4 一致性收口 | W12 | F23/F24 的 P3 与全站一致性 | 视觉层级、语言与模型选择一致，全部路径复验 |

每包可以分成小的可验证提交，完成一个工作检查点即提交并推送已配置分支/远端；
保留其他工作中的文件，不强推。验证后的产品变更按现有规则重新部署本地 Compose，
核对健康与本包功能，记录限制。多个同包子步骤未完成时，不把包状态标为完成。
不预设工期或新的基础设施；实际任务规模由实施前的源码核对确定。

### 前端与浏览器

从仓库根目录执行，依赖已按锁文件准备；需要安装时仅在开发/构建环境执行 `npm --prefix src/apps/web ci`。

```powershell
npm --prefix src/apps/web test
npm --prefix src/apps/web run build
npm --prefix src/apps/web run dev -- --port 5181 --strictPort
```

另一终端指定本次独立输出目录后运行相应包的测试：

```powershell
$env:LIBRARY_BROWSER_URL = 'http://127.0.0.1:5181'
$env:LIBRARY_BROWSER_OUTPUT = '.agent/tmp/ui-ux-<unique-run>/browser'
npm --prefix src/apps/web run test:browser -- quality-navigation.spec.ts ui-contracts.spec.ts optional-review.spec.ts
```

`<unique-run>` 替换为实际唯一目录；有意使用已安装 Chrome 时才设置 `LIBRARY_BROWSER_CHANNEL=chrome`。
默认浏览器测试使用 API 替身，不等于实际持久化；需要写数据的 live 检查只能指向专门的隔离验收实例。
不得把 `LIBRARY_LIVE_BROWSER=1` 指向用户的 8080 实例。只读部署复查不通过该开关扩大写入范围。

### 仓库与隔离后端

选择未使用的测试项目名和数据库端口，显式使用模板：

```powershell
docker compose -p paper-ui-checks -f compose.example.yaml run --build --rm checks
docker compose -p paper-ui-tests -f compose.example.yaml run --build --rm tests
```

`paper-ui-tests` 必须是本次确认独立的临时项目；若已被占用就换唯一名称，后续命令保持一致。
测试端口冲突时先设置空闲的 `TEST_DB_PORT`，不停止用户服务抢占端口。
后端契约改变时增加对应集成测试，里程碑集成后运行完整隔离套件；
纯前端/文案包使用相关前端及浏览器检查，不为形式重复所有模型测试。
清理仅针对本次测试项目，确认目标与生产不同后才执行：

```powershell
docker compose -p paper-ui-tests -f compose.example.yaml --profile tests down --volumes
```

不能 profile 整体 `up`，不能对用户实例运行清库或 `down --volumes`。
历史证据缺失导致的 skip 单独报告，不计为通过；新阅读模板必须有自己的实际输出证据。
