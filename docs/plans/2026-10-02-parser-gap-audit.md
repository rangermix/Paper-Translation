# Independent Astra audit: full-page DMR output → source IR → consumers

Date: 2026-10-02. Baseline: `47c01be` (`main`). Scope: Surya OCR 2, Chandra OCR 2, Infinity-Parser2 Pro and Flash. Read `AGENTS.md`, `.agent/memory/current.md`, product baseline, parser/IR/recovery/translation/editor/render/export code and tests. The current handoff contains older model-selection statements; current source and pinned manifests take precedence for this audit. No runtime code, installed migration, existing snapshot or publication was edited. The unrelated untracked `apps/` directory was left alone.

**Conclusion:** selecting the four models and renaming the shared adapter does not complete their useful-information bridge. Current decoders intentionally reduce rich output to Docling-shaped plain text. This loses scientific meaning, block structure, relationships and edit/render fidelity before translation. Some bridges fit schema 3.0, but complete preservation of the documented semantics needs an explicitly versioned successor source/render contract and compatible consumers. A raw audit file is necessary evidence, but does not make lost usable semantics available to translation or the reader.

Severity: **P1** loses or changes source meaning, discards recoverable content, or silently mishandles a valid output; **P2** loses useful structure, traceability or usability; **P3** bounded optional evidence/compatibility improvement. These are implementation priorities, not publication gates. Content uncertainties remain nonblocking; invalid execution identity, unsafe resources and version conflicts remain actual failures.

The GitHub sources above were resolved to exact commits on the audit date. Those SDK commits are additional contract evidence, not a claim that every SDK behavior is encoded by the older pinned model weights. The selected models do not document genuine rotated polygons, character-level boxes, explicit cross-block IDs or calibrated per-token-to-source spans in this particular raw full-page route. Missing such information is a capability boundary, not evidence of a decoder dropping a field it never receives. If future model contracts provide it, retain it with an explicit coordinate/frame and evidence scope.

Nested layout attributes require care: Surya's official full-page parser deliberately removes nested data-bbox/data-label attributes from inner HTML. Nested semantic tags are useful structure; they are not evidence that every nested debug rectangle is an independent source block. Default to the contracted outer block geometry, retain raw nested attributes in audit, and only use a finer rectangle when its frame and role are established. [Full-page parser](https://github.com/datalab-to/surya/blob/a2363d3311773a2b6145a40458043211c50c52f4/surya/inference/parsers.py).

Backend/version dependencies are material. The pinned Infinity model cards still show vLLM 0.17.1, whereas the current official SDK README at the exact GitHub commit above requires vLLM >=0.26.0; its native engine requests a 65,536 context and 32,768 output tokens. The repository documents the latter prerequisite and its optional translation runner is 0.19.1. These are different documented generations; record which contract is implemented instead of treating an engine-name prefix as version certification. Current `Manager.verify_backend` checks only `Running: vllm ` or `Running: vllm-metal `, and runtime identity omits actual backend package versions. DMR packaging success and matching content ID do not prove architecture/image-input support on CUDA or Metal. Chandra's current wrapper uses a 12,384 output allowance and 192 DPI; Surya has model-specific full-page settings. Repository VLM requests universally use 8,192 output tokens and 32,768 context. Larger upstream allowances are relevant to truncation risk, not a directive to reserve impossible context or claim all pages need the maximum. [Current Infinity SDK requirements](https://github.com/infly-ai/INF-MLLM/blob/9a93df02e725ee98ccd545d02580ec2c12c203ae/Infinity-Parser2/README.md), [engine configuration](https://github.com/infly-ai/INF-MLLM/blob/9a93df02e725ee98ccd545d02580ec2c12c203ae/Infinity-Parser2/infinity_parser2/backends/vllm_engine.py), [Chandra settings](https://github.com/datalab-to/chandra/blob/d4f7467435aa4137d9539f000ddf0b7ced3eb43f/chandra/settings.py).

## Scope of a minimal useful bridge

A neutral intermediate block/inline representation is needed between model-specific decoders and the common source builder. It should carry exact visible text, typed semantic runs, outer reading order, real/inherited PDF regions, original label/role, and a pointer to immutable raw evidence. It must not be a Docling object in disguise with rich metadata that the common builder ignores. Model-specific output forms remain distinct: HTML layout for Surya/Chandra, JSON layout with category-specific Markdown/HTML/LaTeX for Infinity.

Use current 3.0 semantics wherever sufficient: headings, paragraphs, flat list items, math/code atoms, safe links/xrefs, captions, references, exact table grid/spans, code language and multiple PDF locators. Add only useful missing semantics: scripts/deletion/static controls; nested list/cell grouping; table header roles; scoped relationships; provenance range/precision when actually supplied.
