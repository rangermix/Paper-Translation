**2026-09-08 用户补充：质量问题与段落定位。** 校对工作台将阻断与风险提示分组，并提供全部/仅阻断/仅风险筛选及对应段落跳转。阻断段落明确标为必须处理，不能显示可选核对；人工确认不能代替修正和重验。段落可独立折叠，非阻断段落默认折叠，跳转自动展开，折叠和筛选必须保留未保存文字与修改理由。数字检查仅作机械等价比较，不改写原文或已保存译文：统一千分位、PDF提取的小数间隔、数位宽度和明确的中英文数量单位（如 11 billion = 110 亿、3 billion = 30 亿）；仍检查精确数值、正负号、百分号和出现次数，并展示差异证据。规则版本改变使旧 QA 过期，重验后才可封存。

**2026-09-07 用户补充：取消译文强制人工核对/确认。** 段落确认、语义和术语问题核对均为可选；未确认或未处置的高风险提示不阻止封存、手动发布、自动发布或导出，提示及实际核对状态仍保留。缺段、数字/保护原子不一致、资源损坏等硬完整性问题和过期 QA 仍阻断。修改后只需重跑本地质量检查，不要求再次人工确认。此补充覆盖下文旧的强制核对表述；外发授权、未知请求风险处理及来源修正证据规则不变。

本章保留此前可靠性要求，但去掉身份、权限和多租户逻辑。使用者是一个实例的唯一维护者；多个浏览器标签和Worker仍可并发。

## 1. 业务状态与执行状态分离

```text
PDF接收 → inspecting → source_only (M0)
                         │ M1开始解析
                         ▼
parsing → preflight → translating → checking → needs_review / ready
                                                │ 修正/重验
                                                ▼
sealed → building → verified artifact → published
```

业务job的`stage`与操作状态分别存储；`paused/cancel_requested/cancelled/failed/outcome_unknown/waiting_config/waiting_budget`不等于业务完成。已发布旧版与新job的状态分开展示。`source_only`是成功保存原件，不是成功翻译。

结构預检逐页显示已覆盖文本、图表、允许排除的页眉页脚与未解决区域。每个正文区域必须进入来源树或未解清单；检测到一页扫描正文不能以“已提取其他页”继续。M1不支持用户选择跳过失败页生成完整译文。

## 2. 任务领取与租约

Task拥有pending/leased/succeeded/failed/cancelled状态；Attempt独立记录一次尝试。PostgreSQL短事务`FOR UPDATE SKIP LOCKED`领取合格task，递增fence与attempt，写lease_expires，提交后才执行耗时工作。租约默认60秒、每15秒续租；可配置，按真实任务延迟测试。网络和解析期间不持行锁。[S6]

提交内容时要求(task_id,fence,control_epoch)仍匹配。失效Worker可以提交幂等计费证据，但不能修改当前译文、复活删除文档或发布。成功单元立即持久化；恢复只运行缺失且安全重试的单元。

## 3. 外部派发许可

每次调用前，以事务锁定job和预算记录，确认未暂停/取消/删除、外发确认有效、profile/source未变、有足够额度。原子创建DispatchPermit与预算预留后才发网络请求。

**暂停成功** 代表之后不再创建新许可，不意味着之前已发出的请求可撤销。许可一旦发放，保守地视作在途；若进程在真正发送前崩溃、无法证明未发送，也可能进入unknown。不得为了展示即时停止而释放潜在已计费额度。

## 4. 重试与未知结果

能够证明未发送的连接故障，以及供应商明确表明未执行的限流响应，才允许自动退避重试。429并非在任何供应商都能直接断言未计费，适配器必须按其实际语义分类。默认至多3次传输尝试，至多1次付费结构修复。永久认证/模型配置错误停止，不自动切模型。

请求已发送后读超时、断流、进程退出，结果记`outcome_unknown`。若供应商实际提供可用的request_id查询或幂等能力才使用；不得虚构端到端去重。默认暂停，保留未知成本的保守预留，展示“可能已计费”。维护者核对或明确接受重复收费风险后，才能新增attempt；旧未知成本仍计入潜在上限。

SDK隐式重试必须禁用，所有重试都走相同账本。FakeProvider可制造超时但已执行、迟到、错ID、截断等；Fake测试通过不等于真实供应商行为已经证实。

## 5. 预算账本

使用整数微货币金额，PriceSnapshot绑定币种、输入/缓存输入/输出/推理等实际计费维度、版本、估算规则和生效时间。无可信请求成本上界时不能启用“严格限额保证”；应等待配置，而不是用0代替未知费用。

```text
可派发余额 = limit - settled_actual - active_reserved - unresolved_risk
```

三个扣减集合互斥，同一attempt的unknown风险不能同时重复算入active_reserved。允许派发前，以估计输入tokens及最大可计费输出/推理tokens保守预留。实际用量结算释放差额；收到迟到用量时按attempt唯一键幂等结算。实例与job的预算必须同时检查；两份文档争用最后额度至多一个获许可。

这约束的是已知计价规则下的本地派发，不是对供应商账单、费率临时变动或不可核对token计数的绝对保证。UI同时显示估算、实际、预留与未知，不把估算写成真实消费。

## 6. 翻译单元与缓存

同一章节的短块可以合并请求，长块拆unit并保存owner_block_id/unit_order与重组规则。受保护原子不能切断。模型按unit_id返回，集合必须与请求双射；禁止仅用数组位置对齐。完成原因正常、非拒绝、无截断才可提交。多次修复仍不合法进入needs_review/failed。

精确缓存键包括源内容、上下文、locale、provider/model/profile、提示、术语、归一化、分块版本。缓存是全实例内部数据，不含workspace键；跨文档ID映射必须确定且再验证保护原子。人工修订只在M2明确保存到个人翻译记忆，不静默覆盖机器精确缓存。

## 7. 质量检查与人工确认

| 类型 | 规则 | 能否忽略 |
|---|---|---|
| 源完整性 | 全文覆盖、阅读顺序、必需资产 | 不能；先修正来源或明确不支持 |
| 结果结构 | 缺/重/未知ID、空译文、截断、AST非法 | 不能 |
| 保护内容 | 数字/单位、变量、引用、公式、代码次数和内容 | 不能无理由放过；必要格式变体用明确规则 |
| 引用资源 | table网格、xref、脚注、文件hash、图片 | 不能 |
| 语义风险 | 遗漏、否定、条件、比较、术语冲突 | 可选原件对照；保留提示，不阻止发布，不生成虚假确认 |
| 明示保留 | 原图/无法可靠恢复的公式/表格原图 | 只有范围允许且可见说明时接受 |

QA指纹绑定source hash、target snapshot/generation、glossary、规则版本和必要profile。任何目标修改使对应人工确认失效、全局QA过期；机器检查不得生成human_reviewed。人工确认记录origin=manual_ui、时间、源/译指纹与说明，不记录虚构用户身份。

独立模型语义评审是M2可选、默认关闭的付费任务，只产生有定位的issue，不直接写译文；同样走预算和外发确认。模型评分不是准确率。

## 8. 静态发布事务

先封存指定源/译/QA，再在staging构建全部文件；校验引用与hash，写入新artifact前缀，确认可读后以Edition generation CAS更新指针。原子rename只在同卷使用，不能假设数据库与文件系统天然一个事务。

崩溃发生在切换前：旧版继续可读，未引用的孤儿新产物可回收。切换后：所有文件已经完整；若存储后续损坏，返回明确错误而非拼接其他版本。回滚仅选择同Document+locale完整的旧artifact，新事件增加generation。禁止原地覆写已发表HTML。

删除与发布竞争时先检查tombstone和control_epoch，再CAS。取消已先提交则不发布；如果发布先提交，后续取消不回溯抹掉已发表版，UI明确记录操作顺序。

## 9. 个人部署仍需的输入安全

PDF签名和扩展名只是初筛，必须受限解码验证。限制体积、页数、对象解压、图像像素、CPU/内存/时间。禁止执行PDF JavaScript、Launch、外部链接、嵌入附件及动作。parser没有网络、DB或模型密钥；worker将输出当作不可信数据重新校验。

source文字和模型输出HTML转义；受限IR白名单渲染，清除危险协议/属性。SVG等复杂资产优先栅格化或严格处理，不直接信任。禁止目录穿越、symlink、任意文件路径、命令注入。请求保护采用Host白名单、无通配CORS、写请求Origin/自定义同源标识检查；这不能阻止已能直接访问HTTP端口的人操作，不宣传为鉴权。

app无登录，app文件响应不检查用户权限；只复核资源存在、归属关系、manifest、删除状态。数据库密码只是服务间技术连接配置，不形成产品账户。凭据只注入需要它的进程，默认日志不含全文/密钥，Compose secret不等于宿主文件已加密。[S3]

## 10. 生命周期与恢复

归档只从常规列表隐藏；撤销发布只清当前指针；永久删除先tombstone禁止在线读/新任务/迟到写回，然后清理原件、IR、译文、候选、TM、索引、产物和导出，共享资产按引用计数回收。备份按明确期限淘汰，不声称即时擦除备份或已下载副本。

备份通过Compose内CLI进入维护模式：停止新写/新许可、等待本地事务结束、保守登记在途unknown、数据库导出+复制不可变卷+manifest。恢复以维护模式启动，验证hash/引用/schema，禁外发直到核对unknown。不要把旧queued快照直接当“从没调用过模型”。恢复和维护不是Web导入ZIP/JSON的后门。
