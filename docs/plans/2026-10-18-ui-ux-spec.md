# UI 与 UX 改进规格

状态：规格已整理，实施尚未开始。日期：2026-10-18。
本规格把当前部署审查的全部 24 项发现、30 组文案及 12 条页面路径转为需求；
实施顺序见 [优先级计划](2026-10-18-ui-ux-plan.md)。这些是增量改进，不能据此认为上传、解析、翻译、编辑、发布、导出等既有能力尚未实现。

## 1. 目标与依据

用户上传 PDF 后能理解本次处理内容、找到进度、开始阅读、按需修改译文并导出；
无需理解内部版本、执行记录或 IR 结构，也不会因导航丢失输入或误判译文状态。
优先修复操作保护和关键路径，再降低页面理解成本，最后统一视觉细节。

当前 [产品边界](../product-baseline.md)、[工作流](../workflows.md)、
[任务模型](../task-model.md)及并发/不可变契约继续有效。
报告建议与契约冲突时，本规格明确收窄建议，不改写已安装数据来迎合界面。

内置浏览器产生裁切/失真的 `02*` 截图被排除，不作为产品缺陷。

### 必须保留的已有优点

- 深色与青绿色的一致视觉风格，清晰的选中导航和文库阅读入口。
- 独立原文 PDF 入口、原译区分、目录、稳定段落锚点、引用和 PDF 对照。
- 上传的类型、数量、大小和页数限制说明。
- 内容提示与执行失败分开，提示不阻断阅读和后续处理。
- 设置中的已配置/未测试、模型下载状态等真实状态区分。
- 已抽查的手机阅读正文没有横向溢出；改造不能倒退，但该样本不代表所有页面通过。

## 2. 范围与产品约束

1. 仅 PDF、单实例、Compose 部署；不引入账号、角色、工作区、ACL、云同步或新的宿主模型服务。
2. 原文只能来自解析结果或有 PDF 证据的机械修正；不让翻译模型改原文、生成网页或为了目录补写章节。
3. 内容质量提示继续非阻断；保留检查、确定性恢复、原图对照。执行故障、资源损坏、非法路径、缺少外发授权、并发冲突按原规则处理。
4. 不删除语言/locale 差异，不默认勾选人工核对，不伪造完成、已测试、已保存或已发布状态。
5. generation、CAS、fence、租约、幂等和请求结果未知的保护继续有效。界面简化不能把独立操作合并成一个状态。
6. Provider key 仍只存后端 secret 文件；不回显、不写浏览器、日志、导出或解析器。保存设置不自动测试、不下载模型、不切换服务或模型。
7. 已创建任务保留配置/凭据修订快照；未知金额仍为 `null`。金额控制可选，已有选择不变，默认请求与正文上限不因 UX 改造变化。
8. 已安装迁移、源/译封存快照、历史模板和发布资源不可原地修改。需要新阅读资源时注册新模板；先验证完整不可变文件，再按 CAS 切换指针；换样式不重译。
9. 不清理生产数据、不重建持久卷；真实服务/硬件验证需要相应范围的明确授权，测试替身不得当作真实服务证据。

## 3. 设计决策与通用行为

“必须”约束用户结果和兼容边界；具体页签、抽屉宽度、字体与间距可在同等结果下调整。
本轮默认保留现有主导航和路由，不以重新设计整个站点为前提。
“文库 / 处理任务 / 翻译工具 / 设置”可作为信息分组方向，搜索与上传保持明显入口；
不强制把术语表、翻译记忆合成新路由，也不删除现有深链接。
文档范围内让阅读、编辑、版本、导出容易找到，技术详情按需展开。

所有改动覆盖载入、空、成功、失败、未保存、处理中和过期/冲突状态中适用的部分。
焦点移动与视觉顺序一致；图标有名称，状态不只靠颜色。
加载或错误不能显示成空结果；本地未保存不能显示成服务器已保存；
源文阅读、部分译文、完整译文和人工核对是不同维度。
新组件优先复用当前 React/CSS 与既有数据，不为这轮改造默认更换框架。

优先级沿用审查：P1 共 6 项，影响输入、核心路径或内容状态；P2 共 16 项，减少高频理解和操作成本；P3 共 2 项，改善视觉和选择便利性。
这是体验优先级，不是安全漏洞等级；实测发现更严重的可访问性障碍时按影响提前处理。

## 4. 逐项需求与验收

### F01 未保存的译文会在离开页面后丢失

优先级：P1。交付包：W01。

**审查观察：** 在 ZeRO 草稿 b3 的最后一个文本框追加临时标记，点击侧栏文档库，再回到同一草稿：文字恢复为原值。离开时没有确认，未点击任何保存按钮。

**需求：** 未保存状态必须覆盖整份当前编辑草稿，不能只存在于已展开的段落组件。应用内跳转、浏览器前进/后退、刷新版本、应用候选、切换草稿和离开编辑页前，先处理受影响的未保存输入。提供“继续编辑 / 放弃修改 / 保存后离开”；不能完成保存时保留输入并停留，说明原因。修改理由等既有保存条件仍适用，不能由系统虚构。多段保存部分成功时，已成功项与未成功项分别显示，不能把整批标成成功。

刷新或关闭标签页时，在浏览器支持的范围内使用原生离开提示；取消后保留当前输入。默认先交付集中内存状态与离开保护，不自动引入浏览器持久化。报告中的本地恢复作为可选增强：若实现，限标签页会话范围，标明“仅保存在此浏览器，尚未保存到文库”，与文档、草稿、源版本、段落基准版本关联；恢复不自动覆盖服务端或提交。保存成功或明确放弃后清除对应副本，存储不可用时明确提示并保留当前内存输入。不得缓存密钥、服务秘密或整份后端配置；不承诺浏览器崩溃、用户清除存储或关闭会话后的恢复。

**验收：** 修改两段后分别测试侧栏、直接修改 hash、后退/前进、刷新版本与页面刷新；取消离开后输入、选择与修改理由仍在。保存失败、理由缺失、CAS 冲突和部分成功都不能丢字。第二标签页产生新版本后，本地输入仍携带旧基准并进入比较/合并，不静默覆盖；若加入恢复副本，再验证重新载入后的版本隔离。

证据：步骤 6；interaction-evidence.json；截图 10。

### F02 手机端任务详情被埋在 30 条列表之后

优先级：P1。交付包：W02。

**审查观察：** 390 × 844 下直接打开失败任务路由，页面停在 y=0；详情标题在 y=5873，前面是当前页 30 条任务，整个页面高 7981。用户很容易以为没有打开成功。

**需求：** 在现有窄屏断点内，选中任务后直接显示该任务详情；任务列表不再排在详情前。详情有“返回任务列表”，保留筛选、分页、滚动位置和键盘焦点。桌面可保留列表与详情并排；直接链接和刷新不依赖先访问列表。找不到、已清除或无法读取任务时显示相应状态及返回入口。

**验收：** 390×844、768px 和 1100px 宽度分别从列表进入与直接打开详情，首屏能看到任务名、状态及返回入口。返回保留原列表位置；桌面 1440×1000 保留可用的并排布局；空列表、最后一页和删除后返回可用。

证据：步骤 3；截图 23；interaction-evidence.json。

### F03 尚未翻译的原文被放进“译文 · 简体中文”

优先级：P1。交付包：W01。

**审查观察：** 当前草稿的 b3 右侧显示整段英文，标题却是“译文 · 简体中文”。源码确认空 target_inline 会回填 source_inline。文档已有发布版本，也不能据此认为当前草稿已经翻译。

**需求：** 译文存在与否依据当前草稿的真实目标内容及状态判断，不依据文档已有阅读版，也不能通过“文字是否中文”猜测。空目标显示“尚未翻译”，原文回填仅作为明确标注的参考。若提供“以原文开始编辑”，必须是显式动作，产生未保存编辑，不伪造翻译完成或人工确认。区分未翻译、部分完成、已有译文、保留原文、未保存修改；人工核对状态单独表达。页头说明当前草稿与当前阅读版的关系。

**验收：** 用空目标、部分目标、合法同语言译文、保留原文和已有发布版但新草稿为空的样本检查状态。展开、刷新、恢复副本及保存后，标签与真实内容一致；不会把只读原文当作已生成译文提交。

证据：步骤 6；截图 10；segment-editor.tsx:24,64。

### F04 手机端先出现执行按钮，后出现处理方式和服务说明

优先级：P1。交付包：W03。

**审查观察：** 390px 宽度下，“上传并开始处理”位于 y=539；“处理方式”位于 y=642；服务目的地位于 y=934。用户先遇到提交按钮，才看到执行内容。此次未选择文件或实际上传。

**需求：** 桌面和手机共享逻辑顺序：选择 PDF → 本批处理方式与翻译语言 → 实际服务及发送内容摘要 → 提交。选择模式后主按钮分别为“上传并翻译”或“上传并生成原文阅读版”。影响处理和外发范围的信息在提交前可见；滚动布局不得让浮动提交遮挡这些信息。服务名称、实际目的地、模型和必要费用状态可理解、可展开核对。

保留现有“选择解析并翻译并提交即授权本批次”的语义，不增加重复同意框；绑定当前公开配置 hash，配置变更冲突时提示重新确认。原文阅读模式不授权翻译。保留 PDF 类型、批次数量、大小、页数限制、启用金额控制时的预算以及逐文件失败反馈。

**验收：** 键盘和移动视觉顺序一致；两种模式的语言、服务说明与按钮一致。无文件、无可用服务、预算缺失、混合有效/无效文件、配置过期和重复点击均有正确反馈。请求替身验证原文模式不发翻译授权，保存设置不触发测试。

证据：步骤 2；截图 21；interaction-evidence.json。

### F05 一个句子被拆成多个独立编辑框

优先级：P1。交付包：W04。

**审查观察：** b3 的译文输入包含多个文本框：长段落、Trillion、parameters using today、单独的撇号、s hardware.；“保护内容：1”独占一条。用户改一句话需要理解内部 inline 结构。

**需求：** 普通文字按连续段落编辑，用户无需逐个操作 IR 节点。保留文本样式、xref 身份与链接目标、受保护 atom、公式、脚本和顺序；只允许修改既有契约允许编辑的文字。保护对象以可识别的行内对象显示，不允许选择跨对象删除时静默损坏引用；说明受保护原因并保留 PDF 对照入口。

默认采用能忠实往返现有 Inline 结构的段落编辑组件，不预设引入富文本框架。不得用纯文本拼接/正则拆分牺牲结构，也不把所有数字自动标为不可编辑。编辑操作接入 F01 的未保存管理和现有段落保存、修改理由、版本冲突流程。

**验收：** 跨多个普通文本节点选取、输入、撤销/重做、复制粘贴、中文输入法组合、键盘移动和长段落滚动连续可用。包含强调文本、xref、多个相邻 protected_ref、公式和非拉丁文字的样本编辑再保存，未改字段和引用不丢失；恶意 HTML/链接不产生可执行内容。

证据：步骤 6；截图 10；editor-dom.txt；segment-editor.tsx:10。

### F06 手机菜单的键盘焦点留在遮罩后的页面

优先级：P1。交付包：W02。

**审查观察：** 打开菜单后焦点仍在“打开菜单”；按 Tab 到了菜单外的顶部“上传 PDF”；按 Esc 菜单仍然存在。

**需求：** 当前有遮罩的手机导航按模态抽屉实现：打开后焦点进入菜单，背景不可交互，Tab/Shift+Tab 在抽屉内循环，Esc 和明确关闭按钮可关闭，关闭后焦点回到触发处。路由选择关闭菜单并将焦点移到新页面的合理位置，保留当前导航项语义和可访问名称。若改成非模态导航，须同时取消模态遮罩和阻塞语义，不保留半套模式。

**验收：** 键盘、触屏、屏幕阅读器分别检查打开、循环、关闭、选中路由和断点切换。菜单外按钮不能在模态打开时收到焦点；关闭/重开不残留滚动锁或 inert 状态。

证据：步骤 12；截图 22；interaction-evidence.json。

### F07 译文编辑首屏几乎没有正文

优先级：P2。交付包：W04。

**审查观察：** 在 1440 × 1000 下，页头、十余项操作、质量状态和 0 条问题面板几乎占满首屏。实际段落在屏幕底部才开始。

**需求：** 编辑正文为主区域；页头仅保留论文/语言/保存状态、当前草稿关系和高频动作。检查、重译、翻译依据、版本与源文修正按任务组织并按需展开。未检查、检查中、无发现和有提示分别表达；零发现使用紧凑状态，不呈现大片空面板。批量动作与选择范围关联，选中后清楚显示作用段落数。

**验收：** 1440×1000 初次打开含正文的草稿，不滚动即可看到并开始操作首段；390px 能快速进入正文。展开工具不覆盖编辑内容，收起不丢失输入或检查结果；批量范围可核对。

证据：步骤 6；截图 09。

### F08 “全部段落”和数量的口径不一致

优先级：P2。交付包：W04。

**审查观察：** 编辑器显示“417 段”和“显示 242 段”，筛选是“全部段落”。解析页说明这份数据包含 242 个正文块和 175 个原样保留块，编辑页没有解释。

**需求：** 页头分别显示可翻译段落与原文保留内容数量，筛选名符合实际集合。“全部可翻译段落”不暗示包括所有原文块；提供查看保留原文内容的入口。主动定位到筛选外内容时解释临时展示原因。计数使用真实数据和层级定义，不能固定写死 417/242/175，也不把所有 IR 块都称作段落。

**验收：** 审查样本可解释 242 个可翻译块与 175 个原样保留块；其他样本、筛选、有提示例外与深链接定位的总数/显示数一致。没有“消失的内容”，原文保留项仍不可误改为译文。

证据：步骤 5、6；截图 09、24。

### F09 文档管理页的技术信息与操作层级需整理

优先级：P2。交付包：W05。

**审查观察：** 文档库已有显著的阅读入口，详情页承担管理职责合理。但左侧主要区域首先展示 SHA-256、文件属性、匹配信息；常用操作与重新解析、归档、永久删除的层级不够清楚。

**需求：** 保留文档详情的管理定位。标题、作者、语言、状态和高频管理动作优先；哈希、文件校验和内部匹配信息收进可访问的技术详情。常用操作与归档、重新解析、永久删除分组；不可逆动作继续有明确对象和后果说明。按未处理、处理中、可阅读、失败等真实状态呈现可执行动作；文档库仍保留醒目的阅读入口。将“阅读译文”设为管理页主按钮属于设计选择，不是硬性要求。

**验收：** 不同状态下能找到阅读/处理/编辑/历史等合适入口；技术详情可展开；删除不会与普通操作混淆。修改布局不改变重新解析、归档、删除的权限、取消/fence 或确认语义。

证据：步骤 4；截图 08。

## 7. 验证与完成定义

每项完成需满足其行为验收和对应文案，记录源码提交、环境、命令、结果和剩余限制。
前端替身测试证明交互契约；隔离 API/数据库测试证明保存、并发和历史语义；
当前部署复查证明选定机器上的页面表现。三类证据不能互相替代。

响应式至少覆盖 390×844、404px、768px、1100px 与 1440×1000；
补充长标题、大量段落/提示、200% 缩放、键盘和暗/亮/系统主题。
精确坐标不是验收目标，任务可达、内容保留和状态正确才是目标。
实体触屏与屏幕阅读器若无法运行，应列为未完成验证，不用桌面模拟声称通过。

模态导航参考 [W3C 对话框交互模式](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)。
点击目标结合 [WCAG 2.2 目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)的间距和例外逐项检查；
颜色、焦点和缩放同样需要实际测量，本规格不宣称已通过完整 WCAG 审计。

正式执行入口与范围见 [测试说明](../../tests/README.md)和 [浏览器检查](../../tests/browser/README.md)。
所有 24 项需求、30 组文案与 12 条路径均须有对应结果；测试跳过、旧报告和源码存在不能标记为当前验收通过。
完成的实施计划将收口到现行说明，避免长期维护重复的“尚未实现”清单。
